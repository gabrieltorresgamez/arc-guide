## Explanation

Phase C of TOGAF covers data architecture. TOGAF is a framework for enterprise architecture (see the article TOGAF). Phase C has two stated aims. First, it develops a Target Data Architecture that supports the Business Architecture and the Architecture Vision. Second, it uses the gaps between the baseline (current) and target data architectures to identify candidate parts of the Architecture Roadmap.

Before this work starts, the phase needs inputs. This article covers three of them.

- **Statement of Architecture Work.** This approved document sets the scope of the architecture project. It also outlines the objectives and deliverables.
- **Architecture reference materials.** These guide how the Data Architecture is developed.
- **Data principles.** These act as guiding principles for the Data Architecture. See the articles Data Architecture Principle and Architecture Principle.

Think of inputs as the starting kit. Scope, guidance and principles give the target data architecture something to anchor to.

## Example

A company starts a project to unify customer records. The project's scope document says which systems are in the effort. The team also has company rules about data, and some existing reference materials. With these three inputs in hand, the team begins to describe the target data architecture. It then compares that target with today's data to find gaps.
